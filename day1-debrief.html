02 · The Terminal

Talking directly
to the computer.

The terminal is a text interface to the operating system. No clicking, no icons — just commands. It's faster, scriptable, and it's what every professional developer uses to navigate, build, and deploy.

04 · Git & GitHub

Never lose your
work again.

Git takes snapshots of your code called commits. Each commit records what changed, who changed it, and when. If something breaks, you can roll back to any previous snapshot.

GitHub is where those snapshots live online. It's a backup, a portfolio, and a collaboration tool — all at once. Today Freddie created his first repo.

git init

Starts Git tracking in a folder. Run once per project. Creates a hidden .git folder that stores the history.

git add

Stages files — tells Git "include these changes in my next snapshot." You choose what goes in each commit.

git commit

Takes the snapshot with a message. Commit messages are how you (and teammates) understand what changed and why.

gh repo create

GitHub CLI command that creates a remote repo and pushes your code to it in one step. No browser needed.

05 · CSS & JavaScript

Making it look good.
Making it do things.

HTML is the skeleton. CSS is the skin — colours, fonts, spacing, animation. JavaScript is the brain — logic, events, interactivity.

Today's diary used three interesting techniques:

Canvas API — the binary rain

The falling 1s and 0s are drawn using the HTML Canvas API — a JavaScript tool for drawing graphics pixel by pixel. A setInterval calls the draw function 25 times per second, giving the illusion of movement. Each column of characters has its own drop position tracked in an array.

CSS 3D Transforms — the book flip

The page flip is pure CSS. Setting perspective on a parent and rotateY(-180deg) on a child creates a genuine 3D rotation. backface-visibility: hidden hides the back face so you see the next page behind it instead.

Auto-capitalise after a full stop

A keydown event listener fires on every keypress. It checks if the text before the cursor ends with ". " — and if so, intercepts the letter and replaces it with its uppercase version before inserting it.

localStorage — how the diary auto-saves

The browser has a built-in key-value store called localStorage. It persists across page refreshes and browser restarts — no server needed. Type something below, then refresh this page.

06 · Deployment

Getting it on
the internet.

A site that only runs on your laptop isn't a website — it's a file. Deployment means copying your code to a server that's connected to the internet 24/7, so anyone with the URL can see it.

Today we used GitHub Pages — a free service that turns any GitHub repo into a live website. Two commands. Done.

deploying to GitHub Pages
$ gh repo create freddie-diary --public --source=. --remote=origin --push
https://github.com/fmkeith/freddie-diary
* [new branch] HEAD → main
$ gh api repos/fmkeith/freddie-diary/pages --method POST ...
✓ Pages enabled → https://fmkeith.github.io/freddie-diary/
🌐 fmkeith.github.io/freddie-diary

GitHub CLI (gh)

Instead of clicking around github.com, gh lets you create repos, manage pull requests, and enable Pages from the terminal. Faster and scriptable.

What "live" actually means

GitHub's servers now serve Freddie's index.html to anyone in the world who visits that URL. His laptop can be off. It still works.
